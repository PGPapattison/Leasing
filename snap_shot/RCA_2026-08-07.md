# Root-Cause Analysis — Snap Shot REM Comments Wipe

**Date:** 2026-08-07
**Incident:** 4 REM Comments Leah added Wed evening (2026-08-06) were wiped by the next scheduled rebuild before they synced to ClickUp. Recovered from SharePoint version history v52.
**Impact scope:** Every scheduled rebuild since Commit 2 (REM Comment sync) shipped has silently extracted **0 REM Comments** from the SharePoint workbook, meaning REM comments have been wiped on **every run** since the feature launched.

## Evidence

Log from last nightly run (`31173169805`, 2026-08-07 11:12:50 UTC):

```
[INFO] Extracted Ann's edits from SharePoint workbook: 72 property blocks scanned,
       72 with notes, 0 unit notes, 0 market-rent overrides,
       0 REM ClickUp Comments, 0 Last-Synced stamps.
```

Preceded by 72 identical warnings, one per block:

```
[WARNING] Extraction: no RENT ROLL section found for property block at row 13 (PropertyId=279).
[WARNING] Extraction: no RENT ROLL section found for property block at row 44 (PropertyId=7).
...
```

**Every** property block failed the RENT ROLL scan, so the unit-row loop (which reads col P) never executed for any block.

## Cause

The extractor in `rebuild.py::extract_ann_edits` has a two-part off-by-one:

**Layout of a property block (post-TICAM, current):**

| Offset from banner `S` | Content |
|---|---|
| S | Property banner (e.g. "AMBERWOOD PLAZA") |
| S+1 | Address ("Property ID: 279 · ...") |
| S+2 | TICAM row |
| S+3 | blank spacer |
| S+4 | "DEAL ACTIVITY & NOTES" header |
| S+5 | Broker / Contact |
| S+6 | Broker Calls |
| S+7 | Property Flags |
| S+8 | Vacant Callouts |
| S+9 | Deal Activity |
| S+10 | Broker Active Interest from Weekly Reporting |
| S+11 | Ann's Commentary |
| S+12 | blank spacer |
| S+13 | "RENT ROLL" header |
| S+14 | column header row |
| S+15+ | unit data rows (col P = REM ClickUp Comment) |

**`NOTE_LABEL_TO_KEY` maps 6 labels, not 7:**

```python
NOTE_LABEL_TO_KEY = {
    "broker calls": "broker_calls",
    "property flags": "property_flags",
    "vacant callouts": "vacant_callouts",
    "deal activity": "deal_activity",
    "broker active interest from weekly reporting": "broker_active_interest",
    "ann's commentary": "ann_commentary",
}
```

**"Broker / Contact" is missing.** The renderer (`write_property_block`) writes **7** note rows including "Broker / Contact"; the extractor recognizes only 6 of them.

**The label loop trip-count is 7:**

```python
consumed = 0
misses = 0
while r <= max_row and consumed < 7 and misses < 2:
```

Walk from `r = S+5`:

- `S+5` "Broker / Contact" → **miss** (misses=1)
- `S+6` "Broker Calls" → hit (consumed=1, misses=0)
- `S+7` "Property Flags" → hit (consumed=2)
- `S+8` "Vacant Callouts" → hit (consumed=3)
- `S+9` "Deal Activity" → hit (consumed=4)
- `S+10` "Broker Active Interest…" → hit (consumed=5)
- `S+11` "Ann's Commentary" → hit (consumed=6)
- `S+12` blank → miss (misses=1)
- `S+13` "RENT ROLL" → miss (misses=2) → **break**
- Loop exits with `r = S+14`

**Then the RENT ROLL scan starts at `scan_row = r = S+14`** and looks forward 20 rows for a cell containing "RENT ROLL". But RENT ROLL is at **`S+13`** — one row above the scan start. The scan never finds it.

Every block fails identically. The extractor exits without ever reading col P. The fresh render writes `""` into every REM Comment cell.

## Why this wasn't caught earlier

- The log warning was already emitted on every block on every run, but nobody was watching for it.
- The summary line reported "0 REM ClickUp Comments" but that was the extraction count, not a delta vs. previous run — so it looked like "there just aren't any" instead of "we lost some."
- The TICAM row was added recently (2026-08-06) so this bug appears intertwined with that change, but it's actually independent — the extractor was always going to overshoot RENT ROLL by 1 row given the 6-vs-7 label mismatch. TICAM just happens to have shipped in the same window as the first heavy Leah REM-comment usage, which is why the wipe is only now visible.

# Proposed Fix

## 1. Add "Broker / Contact" to `NOTE_LABEL_TO_KEY` (the direct bug)

```diff
 NOTE_LABEL_TO_KEY = {
+    "broker / contact": "broker_contact",   # extracted but not written back
     "broker calls": "broker_calls",
     "property flags": "property_flags",
     "vacant callouts": "vacant_callouts",
     "deal activity": "deal_activity",
     "broker active interest from weekly reporting": "broker_active_interest",
     "ann's commentary": "ann_commentary",
 }
```

**Note:** we do *not* write `broker_contact` back into `_notes`; the "Broker / Contact" row is auto-populated from the ClickUp Broker Directory on every rebuild, so we just want the extractor to see it and consume a row.

## 2. Make the RENT ROLL scan robust to label-count drift (defensive)

Change the RENT ROLL probe to start from `notes_start` (top of the label block) instead of `r` (post-loop cursor), so even if the label loop overshoots by 1 or exits early, we still find RENT ROLL:

```diff
             # Find the RENT ROLL section within this block and walk unit rows.
-            scan_row = r
+            # Scan from the top of the note block, not from wherever the label
+            # loop happened to stop, so we're immune to future label-count drift.
+            scan_row = notes_start
             rent_roll_header_row = None
-            for probe in range(scan_row, min(scan_row + 20, max_row + 1)):
+            for probe in range(scan_row, min(scan_row + 25, max_row + 1)):
                 if cell_text(probe, "B").upper() == "RENT ROLL":
                     rent_roll_header_row = probe
                     break
```

## 3. **Safety guardrail: refuse to upload if REM Comment count drops** (blocks recurrence)

Add a hard preflight check in `run_build` — after extraction, before render — that raises if the extracted REM Comment count falls to zero *and* the previous run had any. Track "previous run count" in a small JSON file committed to the repo.

```python
# rebuild.py, at the top of run_build after extract_ann_edits returns
def _check_rem_comment_floor(
    current_count: int,
    force_rebuild: bool,
    state_path: str = os.path.join(DATA_DIR, "last_rem_count.json"),
) -> None:
    """
    Refuse to upload if the extracted REM Comment count dropped from a nonzero
    prior value to zero (or dropped by >50%). This catches extractor regressions
    like the 2026-08-07 layout-drift bug that silently wiped 4 REM Comments.

    Bypass with force_rebuild=True (already exposed as workflow input).
    """
    try:
        prior = json.load(open(state_path))["count"] if os.path.exists(state_path) else 0
    except Exception:
        prior = 0

    if not force_rebuild:
        # Hard floor: prior was >0 and we now see 0 → almost certainly extractor bug.
        if prior > 0 and current_count == 0:
            raise RuntimeError(
                f"REM Comment safety guard: extractor returned 0 comments but the "
                f"previous run saw {prior}. Refusing to upload — this would wipe "
                f"REM comments. Re-run with force_rebuild=true to bypass."
            )
        # Soft floor: >50% drop is suspicious.
        if prior >= 4 and current_count < prior // 2:
            raise RuntimeError(
                f"REM Comment safety guard: extractor returned {current_count}, down "
                f">50% from {prior} last run. Refusing to upload. Re-run with "
                f"force_rebuild=true to bypass."
            )

    # Update state atomically after successful check.
    tmp = state_path + ".tmp"
    with open(tmp, "w") as f:
        json.dump({"count": current_count, "ts": datetime.utcnow().isoformat()}, f)
    os.replace(tmp, state_path)
```

Wire in `run_build`:

```diff
     LOG.info(
         f"Extracted Ann's edits from SharePoint workbook: "
         f"{blocks_found} property blocks scanned, {len(property_overrides)} with notes, "
         f"{len(unit_notes)} unit notes, {len(market_rent_overrides)} market-rent overrides, "
         f"{len(rem_comments_by_prop_unit)} REM ClickUp Comments, "
         f"{len(last_synced_by_prop_unit)} Last-Synced stamps."
     )

+    _check_rem_comment_floor(
+        current_count=len(rem_comments_by_prop_unit),
+        force_rebuild=force_rebuild,
+    )
```

Commit `data/last_rem_count.json` to the repo (workflows already `git add -A && git commit && git push` state files after runs — verify pattern matches).

## 4. **Safety guardrail: archive previous version before every overwrite**

Add a `_archive/` folder in SharePoint (parallel to `_recovery/`). Before every `upload_workbook`, copy the current live version to `_archive/Leasing-Snap-Shot__pre_{timestamp}.xlsx`. Keep last 14 days.

```python
def archive_current_snap_shot(access_token: str) -> None:
    """
    Copy the current live Snap Shot to _archive/ before we overwrite it.
    Retention: last 14 days (roughly two full weeks of nightlies + weeklies).
    """
    ts = datetime.utcnow().strftime("%Y%m%d_%H%M%S")
    archive_name = f"Leasing-Snap-Shot__pre_{ts}.xlsx"

    # Download current live copy
    current = download_snap_shot(access_token)  # existing helper
    if current is None:
        LOG.warning("Archive: no current Snap Shot to archive (first run?).")
        return

    # Upload to _archive/ using existing upload helper
    upload_path = f"WORKING DOCS/_archive/{archive_name}"
    upload_workbook_to_path(access_token, current, upload_path)
    LOG.info(f"Archive: copied current Snap Shot to _archive/{archive_name}")

    # Prune archives older than 14 days
    _prune_archives(access_token, retain_days=14)


def _prune_archives(access_token: str, retain_days: int = 14) -> None:
    cutoff = datetime.utcnow() - timedelta(days=retain_days)
    items = list_folder(access_token, "WORKING DOCS/_archive/")
    for it in items:
        if not it["name"].startswith("Leasing-Snap-Shot__pre_"):
            continue
        # Filename: Leasing-Snap-Shot__pre_20260807_081700.xlsx
        try:
            ts_str = it["name"].split("__pre_")[1].replace(".xlsx", "")
            ts = datetime.strptime(ts_str, "%Y%m%d_%H%M%S")
        except Exception:
            continue
        if ts < cutoff:
            delete_item(access_token, it["id"])
            LOG.info(f"Archive: pruned {it['name']} (>{retain_days}d old)")
```

Wire in `run_build`, just before the final upload:

```diff
+    archive_current_snap_shot(access_token)   # always archive before overwrite
     upload_workbook(access_token, workbook_bytes)
```
